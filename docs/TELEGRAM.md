# Telegram 操作教程

[返回首页](../README.md) · [CF 部署](DEPLOY.md) · [Windows](WINDOWS.md) · [Mac](MACOS.md)

以下操作都在你自己的同一个 Bot 中完成。先完成 CF 部署并安装客户端；未经授权的用户不能控制你的设备。

## 1. 机器管理与重命名

发送 /start 或 /machines，打开“机器管理”。点机器名称进入这台机器的控制面板；点“机器管理 / 切换”回到列表，再选另一台。切换页面不启动、停止或修改任何机器。

电脑初始名称通常来自系统主机名。进入 **机器管理 → 选择机器 → 重命名**，按提示输入“家里 Windows”“办公室 Mac”等名称。改名不改变设备身份，不需要重新配对。

点击“添加机器”可获取已预填 CF 地址的 Windows / Mac 命令。v0.2.0 中命令可用于多台电脑，每台运行后输入本 Bot Token 和自己的数字用户 ID；Token 只做绑定校验，不保存在电脑。每次分配独立设备身份。

## 2. 选择会话或新建

### 使用已有会话

1. 选择目标机器。
2. 点击“选择会话”，等待该电脑返回列表。
3. 需要时点“下一页”，选择目标会话。
4. 查看名称、目录和更新时间，确认后返回详情点“开始”。

选择会话本身不立即开始执行。已有任务运行时，先点“立即停止”，再换会话。

### 新建会话

1. 点击“新建并开始”。
2. 选择当前目录、已保存的常用目录，或按提示输入本机绝对路径。
3. 程序在该电脑上创建一个新会话并开始执行。

目录必须存在。Windows 可以填写实际的 C:\Users\你的用户名\Documents\项目目录；Mac 填实际的 /Users/你的用户名/Documents/项目目录。不要把示例用户名原样提交，也不要填写相对路径。

## 3. 设置保持时长和发送间隔

| 设置 | 具体含义 |
| --- | --- |
| 保持时长 | 首次明确成功之后继续保持多少分钟；到期结束当前执行并停止后续发送。 |
| 发送间隔 | 每轮结束后等待多少分钟，再发送下一次“在”；不是每隔固定整点强行并发发送。 |
| 发送内容 | 默认是“在”，可以在卡片中修改。 |

保持时长快捷值：10 / 30 / 60 / 120 分钟，还可选择“不限时”或自定义整数分钟。

发送间隔快捷值：1 / 2 / 5 / 10 分钟，还可自定义正整数分钟；默认 1 分钟。

示例：

~~~text
家里 Windows：保持 30 分钟，发送间隔 1 分钟
办公室 Mac：保持 120 分钟，发送间隔 5 分钟
~~~

设置按机器独立保存。保存后返回同一台机器的面板，按钮直接显示当前值，例如“保持：30 分钟”“间隔：5 分钟”；不限时显示“保持：不限时”。快捷选项用 ✓ 标出当前值，自定义分钟也会显示在按钮上。电脑离线时保存的参数会在重连后同步。

## 4. 计时和停止规则

- 首次明确成功前的等待、失败和重试不占用保持时间。
- 后续成功、失败、重连都不会重新计时。
- 运行中延长或缩短时长，仍从本次任务首次成功时计算；已经超时会停止。
- 修改发送间隔后，按最近一轮结束时间重新计算。
- “立即停止”会中断当前执行并取消后续轮次；等待卡片确认停止后再切换会话。
- 手动停止后再次开始，是一个新任务，重新从首次成功计算。
- 每台机器同时运行一个会话，多台机器可以并行。
- 断线超过 60 秒不开始新轮次；已经知道的截止时间仍由本机检查。
- 电脑睡眠期间无法执行检查，恢复后会先判断是否到期，不补发积压的“在”。

“成功”要求 Codex 返回明确的完成结果。长时间没有输出不会被当作成功。

## 5. 定时任务

进入机器卡片的“定时任务”，选择“添加定时启动”或“添加定时停止”。

| 类型 | 输入格式 |
| --- | --- |
| 一次执行 | YYYY-MM-DD HH:MM，替换成实际的未来日期时间。 |
| 每天执行 | 每天 09:00 等“每天 HH:MM”形式。 |

统一使用**北京时间**，与电脑系统所在时区无关。定时启动使用该机器保存的会话和参数。

保持时长与定时停止同时存在时，先到达的停止条件生效。定时启动时机器离线或错过有效时段，不会在很久之后突然补执行。

在定时列表中点击对应“取消”按钮，可删除那条任务。输入过程中不想继续，可发送 /cancel。

## 6. 切换机器与独立控制

“机器管理”列出全部电脑。选择哪台，就查看和控制哪台；每台保留自己的名称、会话、保持时长和发送间隔。

在同一个面板中切换机器、重命名和修改时间，按钮会原地更新。其他电脑的状态上报不会把当前页面切走。正在输入名称或自定义分钟时切换机器，会取消旧输入，避免误改另一台。

旧消息中的批量按钮已停用，点击会转到机器管理；不会继续向多台电脑发指令。

## 7. 诊断、重启和一键更新

选中机器后，直接点击面板上的“更新程序”；“更多设置”中可以诊断、重启和移除绑定：

| 按钮 | 行为 |
| --- | --- |
| 诊断 | 查看该电脑检测到的 Codex 路径、版本、CLI 登录状态。 |
| 重启客户端 | 停止当前任务，重启本项目客户端；重新上线后待命。 |
| 更新程序 | 下载并校验最新正式 Release，安装后重新上线待命。电脑上不必重新输入命令。 |

**提交代码到 GitHub 并不等于已发布安装包。** 必须等 Release 构建成功、安装包和校验清单发布后，更新按钮才有新版本可用。

更新前确认机器在线，更新期间暂时离线属可能现象。若长期不回来，按系统教程查看本机日志。普通客户端更新不需要重新输入 Bot Token 或用户 ID。设备详情中显示客户端版本，更新后可直接在 TG 核对，不必到电脑操作。

云端 CF 服务不会被这个按钮更新，按 [云端更新教程](DEPLOY.md#9-更新电脑端与云端分别处理)单独处理。

## 8. 移除设备

“更多设置 → 移除绑定 → 确认移除”会使该设备凭据失效。在线客户端会收到停止/撤销操作；离线电脑无法即时收到。

移除绑定不是本机卸载。要删除电脑上的程序、日志和配置，按 [Windows 卸载](WINDOWS.md#卸载与清理)或 [Mac 卸载](MACOS.md#卸载与清理)操作。v0.2.0 卸载器会尝试自动移除该设备云端状态，失败会明确提示。整个系统不用时，还需清理 CF 资源；TG 聊天历史不由客户端卸载器删除。

## 9. 运行状态、重试与返回控制页

点“开始”后立即出现独立的运行状态卡，下面有 **停止 / 继续 / 控制面板 / 返回主页面**。机器完整控制页中也可以点“运行状态”随时查看。

- 每次实际尝试产生一张卡片；同一次尝试的执行中、成功或失败在这张卡上原地更新。心跳不会重复发消息。
- 显示尝试次数、已执行的重试次数、成功轮数、连续失败次数、失败原因和下次重试时间。
- v0.2.4 客户端运行时每 5 秒上报状态；开始尝试和执行结束会立即上报。显示取决于电脑、CF 和 Telegram 的网络连接。
- “执行中”代表 Codex 正在执行，本轮尚未确认成功；只有完成事件与正常退出共同确认后才显示成功。
- “停止”中断当前执行与后续轮次；停止后点“继续”，使用当前选定的会话启动新任务并重新计时。运行中点“继续”不会重复启动或跳过发送间隔。
- 历史任务卡的停止/继续按钮不会控制后来启动的新任务；请使用最新状态卡。
- “控制面板”打开完整机器设置页。“返回主页面”打开机器管理。即使点击历史消息，页面也直接在所点击的消息上更新，不必往聊天记录上面寻找。

旧版客户端也能显示基础运行状态；升级到 v0.2.4 后可以看到准确的尝试和重试次数。处于离线状态时，卡片中的任务数据是最近上报的信息，不能视为电脑的实时状态。

登录失效、权限问题或会话归档可能导致暂停；被桌面端占用则等待重试。需要权限审批的 Codex 操作仍受本机配置约束，TG 不会自动绕过这些设置。
